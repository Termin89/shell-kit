# /components

Скилл доработки UI-компонентов: единица работы — конкретный компонент
(примитив ui-слоя ядра `shell-kit/ui`, блок `src/ui/shared/`, виджет
каркаса), а не фича
модуля. Типичный вход — «Tabs требует анимацию переходов между
табами», «Chip прыгает», «перевёрстай FileRow». Взрыв-радиус — все
потребители компонента, поэтому флоу отличен от feature: сначала слой
и канон, потом код.

## A. Развилка (кто главный)

- Операция над сущностью модуля (права, персистентность, новая
  мутация) → скилл `feature` (`references/ui-patterns.md`).
- Реворк блока без операции в рамках модульной задачи → feature +
  `references/ui-rework.md` (типология приёмов).
- **Сам компонент — единица работы**: несколько потребителей, shared,
  канон/эталон, API пропсов, motion → этот скилл.
- Пул доработок модуля (этапы, гейты) → `improvements`; его
  компонентные пункты исполняются через этот скилл.

## B. Флоу: locate → canon → clarify → implement → verify → propagate

### 1. locate — слой и потребители

- Слой — по классификатору
  `prototype-to-app/references/classifiers/component-levels.md`
  (примитив / блок shared / виджет / страница): где компонент живёт
  сейчас и должен ли жить там после доработки. Слой ≠ масштаб: ранг
  внутри страницы (экран → экранный блок → элемент) — там же,
  секция «Ранги»; ранг задаёт план проверки (blast radius), порог
  декомпозиции inline-разметки в блок и правила «один блок — один
  файл» (владение множеством компонентов — самостоятельный порог,
  экран после декомпозиции владеет только рамкой) и «один экран —
  один tsx в корне» (главный компонент + не-компонентные файлы,
  блоки — в components/ или подпапках режима); там же —
  «Повтор внутри экрана ≠ shared».
- Контракт данных вьюхи — `prototype-to-app/references/vm-contract.md`:
  какой ранг получает vm (срез/под-объект), какой — узкие пропсы
  (критерий: решает ли блок, что рендерить по состоянию экрана).
  Проект не на vm (другой паттерн из семьи) — уточнить у владельца,
  не подменять молча.
- Потребители: поиск по импортам — **все** точки использования; это
  план проверки. Ядро `shell-kit/ui` — библиотека всех приложений:
  правка ядра касаема каждого проекта.
- **Аудит-карточка** по осям `references/component-audit.md`
  (✓ есть / ✗ нет / — не применимо): фактическое состояние компонента
  до правки. Чинится релевантное запросу; остальные дыры — в открытые
  вопросы, не молча.
- `skills/PROJECT.md` проекта (если есть): эталоны, запреты, токены,
  **уровень полировки UI** — `references/polish-levels.md`; нет
  декларации уровня — предложить и зафиксировать этим же ходом.

### 2. canon — приёмы до изобретения

Свериться с готовыми приёмами платформы, прежде чем писать новый:

- **Скользящий индикатор** (Tabs, NavList): `useLayoutEffect` +
  `ResizeObserver`, замер `offsetLeft/offsetWidth`, анимация только
  на переходе (флаг animate-once), ресайз контейнера — мгновенный
  пересчёт без «догона».
- **Enter-only появление** (pageTransition / ModuleRenderer): вариант —
  data-атрибут на обёртке, реализация в CSS, первый mount без
  анимации, тюнинг токенами (`--page-enter-*`).
- **Derived-state поп** (Chip): короткая анимация как производная от
  значения, без эффектов; при мутациях с перечиткой — только useEffect
  с prev-сравнением (два апдейта подряд убивают render-фазу).
- **Высотный FLIP / swap** (useSwapAnimation): контент переменной
  высоты, направление — CSS-переменной, reduced-motion — мгновенно.
- **Скелетон 1:1** (loading, L2): призрак повторяет геометрию
  карточки — кап обложки, line-box высоты, резерв строк одной
  обёрткой; шиммер = дыхание + свип transform-ом; сетка не прыгает —
  `references/loading-media.md`.
- **Фейд-ин медиа** (FeedImage, L2): плейсхолдер на обёртке, фейд на
  img, готовность = onLoad + complete-чек — `references/loading-media.md`.

Правила motion: только `transform`/`opacity` (ползунок — ещё
`translate`/`width`); layout-свойства (height/top) — через FLIP, не
напрямую; `prefers-reduced-motion` — мгновенная смена; первый mount —
без анимации; длительность/изинг — токены проекта, не магические
числа.

### 3. clarify — содержательный гейт (AskUserQuestion)

Таблица «вопрос → дефолт (канон/эталон) → выбор»; повестка — дыры (✗)
аудит-карточки, релевантные запросу (`references/component-audit.md`):

- **Приём**: варианты с описанием эффекта. Пример: вход «анимация
  переходов между табами» — ползунок уже канон Tabs; недостающее —
  контент-swap панелей → enter-only fade против FLIP-высоты.
- **Уровень полировки**: повестка взвешена декларированным уровнем
  проекта (L0/L1/L2, `references/polish-levels.md`): дыры ниже
  уровня — в открытые вопросы, приёмы выше — предложением подъёма
  уровня, не молча.
- **API**: новые пропсы обратно совместимы или ломающие (ломающие —
  все потребители правятся в этом же ходе).
- **Уровень**: подъём/понижение по классификатору; второй потребитель
  в другом модуле — кандидат в shared (повтор внутри одного экрана —
  локальный блок папки модуля), подъём предложением.
- **Мобильное поведение** и **a11y**: role/aria-атрибуты, фокус,
  контраст, клавиатура.

### 4. implement

Компонент + прогон каждого потребителя: правка видна всем — проверить
композицию у каждого (длинные тексты, узкий вьюпорт, disabled-ветки).
`data-name`, семантические токены, примитивы ui-слоя ядра; домена в
компоненте нет (классификатор). Ветвление: тернарник только
плоский; расширяешь его (вложенность, вторая ось, третья ветка)
или гирлянду `&&` — стоп-сигнал: не доращивать, этим же ходом
переводить на derive-once (функция ключа с ранними return) +
реестр (канон и эталон — PROJECT.md проекта, «Ветвление»).

### 5. verify — числа, не глаз

- Переход: `getComputedStyle` ползунка/панели до → в середине → после
  (transform/opacity меняются, layout не дёргается); ширины без
  переполнения (`docW == clientWidth`).
- Утилита проверяется computed-стилем, не классом в разметке:
  Tailwind v4 молча не эмитит класс с несуществующим токеном.
- Живые анимации — `el.getAnimations()` (getAnimationNames в Chromium
  нет); скелетон — замером призрак vs карточка (высоты, top строк
  сетки), не на глаз.
- `prefers-reduced-motion` (эмуляция media) — смена мгновенная.
- Каждый потребитель: DOM-проба первична; скриншот — артефакт ревью,
  не инструмент проверки.
- Приёмка по чекпойнтам затронутых осей аудита
  (`references/component-audit.md`): ✗ → ✓ в карточке.
- Сборка: typecheck / lint / build — чисто; storybook-каталог есть —
  stories на новые ветки поведения.

### 6. propagate — закрепить приём

- Приём повторился или стал каноном → строка-эталон в
  `skills/PROJECT.md`; приём уровня ядра — в readme ui-слоя
  (`shell-kit/ui`).
- Уровень полировки проекта декларирован или изменён → секция
  «UI-полировка» в `skills/PROJECT.md` проекта
  (`references/polish-levels.md`).
- Заметно изменилось поведение экранов → строка в
  `docs/modules/<id>/<id>.md` затронутых модулей.
- Есть `.app-build/decisions.md` → D-запись: уровень, приём, отличие
  от эталона, приёмка.

## C. Правила

- **Канон сильнее вкуса**: расхождение с эталоном — только решением,
  отличие фиксируется.
- Компонент не знает домен; оброс предметикой — понижение уровня с
  D-записью.
- Второго потребителя нет — не поднимаем; появился — подъём
  предложением, не молча.
- **Владение общим**: у каждого места экрана один владелец. Каркасные
  виджеты — владелец каркас (AppState/навигация, без предметики),
  примитивы/блоки — форма без домена, потому связей не создают; «зон
  с владельцем "все"» нет — правило по владению, не по радиусу
  влияния (PLAN.md, «Слоты»; классификатор —
  `prototype-to-app/references/classifiers/component-levels.md`,
  «Владение зонами»).
- Демо-инструментарий (паттерн RoleHint): данные и вёрстка внутри
  компонента, прод-удаление одной точкой.

## D. Точки роста (честно)

- Инвентарь приёмов фазы canon — первый срез; loading/медиа-часть
  стабилизирована в `references/loading-media.md`, остальной motion —
  в `references/motion.md` по мере обкатки.
- `references/component-audit.md` — первый срез осей (9); пример-карточка
  Tabs обновляется при первом реальном прогоне скилла.
- Живые эталоны (Tabs/NavList/Chip/useSwapAnimation) — кандидаты в
  storybook-каталог ядра.
