# Аудит компонента: оси улучшений

Карта «что вообще можно улучшить в компоненте» для фаз скилла
`components`: **locate** строит карточку фактов, **clarify** берёт
повестку из дыр, **verify** принимает по чекпойнтам затронутых осей.
Аудит ≠ «чинить всё»: карточка фиксирует фактическое состояние,
чинится релевантное запросу, остальные дыры — в открытые вопросы
(кандидаты в бэклог модуля/пула). Состав повестки взвешивается
декларированным уровнем полировки проекта
(`references/polish-levels.md`); чекпойнты прод-полировки помечены
**(L2)**.

## Как читать карточку

Ось → чекпойнты → отметка **✓ есть / ✗ нет / — не применимо**.
Эталоны — раздел «Эталоны» `skills/PROJECT.md` проекта и канон
платформы; у чекпойнта без эталона правило написано прямо в тексте.

## Ось 1. Вёрстка и геометрия

- Переполнение: `min-width: 0` у flex/grid-детей; ellipsis длинных
  текстов; инвариант `docW == clientWidth`.
- Худший контент: самый длинный текст/список не рушит композицию
  (проверять именно worst-case, не средний).
- Адаптив: ниже брейкпоинтов — другая композиция, а не исчезновение;
  обязательный вопрос clarify.
- Touch targets ≥44px; горизонтальная прокрутка вместо переноса, где
  уместно (лента вкладок).

## Ось 2. Визуальная система

- Только семантические токены; raw hex/px — запрет; тюнинг — токены
  компонента (паттерн `--nav-indicator-*`).
- Полный набор состояний вида: hover / focus-visible / active /
  disabled / selected — не только default.
- Прототип — драфт-референс, не детальный эталон: стартовая точка
  вёрстки, а не цель. Канон зрелого экрана — устоявшийся вид проекта:
  полировка приводит экраны максимально к одному виду; расхождение —
  решением, не вкусом.

## Ось 3. Доступность (обычно самая дырявая)

- Семантика: нативные элементы (`button`, а не div с onClick);
  role/aria по WAI-ARIA-паттернам (tabs: `tablist`/`tab`/
  `aria-selected` **плюс стрелки**).
- Клавиатура: roving tabindex, стрелки/Home/End, Enter/Space,
  Escape (дроверы/модалки); фокус не теряется после удаления/закрытия.
- Связка контролов: `aria-controls` ↔ `id` панелей; `aria-live` для
  тихих мутаций (оптимистичная отправка).
- Контраст текста/иконок; `prefers-reduced-motion`; icon-only контрол —
  `aria-label`.

## Ось 4. Motion

- Приёмы канона: скользящий индикатор (Tabs/NavList), enter-only
  (pageTransition, data-атрибут), derived-pop (Chip), высотный FLIP
  (useSwapAnimation), шиммер скелетона — дыхание + свип света
  transform-ом по ::after (`references/loading-media.md`).
- Три вопроса раздельно: анимация **входа / выхода / смены** —
  наличие одной не закрывает остальные.
- Правила: только transform/opacity; layout-свойства — через FLIP;
  reduced-motion — мгновенно; первый mount — без анимации;
  длительность/изинг — токены.

## Ось 5. API и поведение

- Контролируемый/неконтролируемый (`value`/`defaultValue`);
  `onChange` идемпотентен.
- Composition over configuration: слоты/children вместо флага на
  каждый случай; варианты — union-проп, не набор булевых.
- Disabled-ветки элементов (вкладка/пункт/кнопка), не только кнопки
  целиком.
- Back-compat: новые пропсы опциональны; ломающие — миграция всех
  потребителей в этом же ходе.
- Демо-инструментарий: данные и вёрстка внутри компонента, удаление
  одной точкой (паттерн RoleHint).

## Ось 6. Логика и стейт

- Derived state без эффектов (Chip); эффекты — только внешний мир
  (замеры/подписки) и с cleanup (Tabs: `ResizeObserver.disconnect`).
- Замеры — `useLayoutEffect` батчем (прочитать всё → записать разом),
  без layout thrashing.
- Async: поздний ответ не перетирает новый (последний выигрывает),
  отмена/флаг размонтирования, stale closures.
- Списки: стабильные key; append-семантика осознана и зафиксирована
  (messenger outbox — квирк в доке модуля).

## Ось 7. Состояния компонента (§48 в миниатюре)

- Компонент с данными: loading (скелетон/спиннер) / empty /
  error+retry / disabled — у себя, а не делегировано странице без
  причины.
- Мутация: pending на кнопке («Сохраняем…» + disabled), двойной
  сабмит исключён; сбой — ретрай на месте.
- Скелетон 1:1 **(L2)**: призрак повторяет геометрию карточки
  (кап обложки, line-box высоты, резерв строк одной обёрткой);
  сетка не прыгает при появлении данных; шиммер + reduced-motion;
  role=status, призраки aria-hidden.
- Медиа-плейсхолдер **(L2)**: заливка до битмапа + фейд-ин
  (заливка на обёртке, фейд на img, onLoad + complete-чек).
- Мутация с инвалидацией не перемонтирует вьюху **(L2)**:
  stale-while-revalidate по ключу записи — локальный стейт
  (поп, фокус, скролл) выживает перечитку.

## Ось 8. Архитектура и контракт

- Уровень по классификатору `component-levels.md`; домен не внутрь;
  подъём/понижение предложением + D-запись.
- JSDoc-контракт: назначение, модель управления, канон происхождения
  (Tabs — модельный пример); `data-name` обязателен.
- Производительность: мемоизация на границах, виртуализация длинных
  списков, правка не увеличивает ререндеры потребителей.
- Эксплуатация: эталон в PROJECT.md / readme слоя, stories каталога.

## Ось 9. Гигиена и безопасность

- Внешние url: только https-схема (никаких `javascript:`),
  `target="_blank"` + `rel="noopener noreferrer"`.
- Никакого `dangerouslySetInnerHTML` без необходимости; текст —
  текстом, не html.
- Тексты не хардкодятся в компоненте общего назначения (демо-блоки —
  исключение); склонения у счётчиков («1 новый / N новых»).

## Пример карточки: Tabs (u-kon, 2026-09-24, до → после прогона скилла)

| Ось | До | После |
|---|---|---|
| 1 Вёрстка | ✓ flex-1/inline; ✗ ellipsis | ✓ truncate + title, min-w-0 |
| 2 Визуальная система | ✓ токены; ✓ focus-visible глобальный | — |
| 3 Доступность | ✓ role/aria-selected; ✗ стрелки, roving, aria-controls | ✓ полный WAI-ARIA (стрелки ←/→, Home/End, автоактивация, roving tabindex, id ↔ панель) |
| 4 Motion | ✓ ползунок; ✗ контент-swap панелей | ✓ useSwapAnimation поднят в shared (swap-surface/swap-anim), оба потребителя |
| 5 API | ✓ управляемый, items-конфиг; ✗ disabled-вкладка | ✗ disabled — открытый вопрос |
| 6 Логика | ✓ замер батчем, observer с cleanup | — |
| 7 Состояния | — (без данных) | — |
| 8 Архитектура | ✓ блок shared, JSDoc-контракт | ✓ + контракт панели в JSDoc |
| 9 Гигиена | — | — |

Повестка clarify была из дыр «до»: клавиатура (3), контент-swap
(4), disabled (5), ellipsis (1). Решения гейта: полный WAI-ARIA;
свап — подъём useSwapAnimation в shared (второй потребитель
requests получил свап тем же ходом); disabled — отложен; ellipsis —
truncate + title. Приёмка: tsc/oxlint/build чисто; DOM-пробы
перехода (translate/width ползунка, height FLIP панели) и
reduced-motion — по канону фазы verify.
