# Контракт фазы

Файл фазы — самодостаточный промт: оркестратор (или субагент) читает
его и выполняет, не зная остального скилла. Единая структура делает
фазы взаимозаменяемыми (L1) и тестируемыми по отдельности.

## Обязательные секции файла фазы

1. **Заголовок + статус** — имя фазы в графе, полнота («полная» /
   «каркас»), реентерабельность.
2. **Назначение** — одна-две фразы: какую проблему фаза закрывает.
3. **Вход / предусловия** — какие артефакты и state-поля должны
   существовать; что делать, если их нет (обычно: отправить на
   предыдущую фазу, не импровизировать).
4. **Наводящие вопросы + дефолты** — список вопросов к пользователю;
   у каждого дефолт и способ его проверки. Дефолт — не угадывание, а
   гипотеза с обоснованием; ответ фиксируется D-записью.
5. **Действия** — пошагово; включают filesystem probing перед записью
   (идемпотентность) и явные метки заменяемых блоков.
6. **Выход** — артефакт(ы) на диске + точный диф state.json
   (какие поля меняются, на что).
7. **Гейт** — тривиальный или содержательный; для содержательного
   перечислены вопросы и варианты с последствиями.
8. **Изоляция записи** — белый список путей, которые фаза (и её
   субагенты) вправе создавать/менять. Всё вне списка — патч-предложение
   оркестратору.

## Шаблон

```markdown
# Фаза: <name>

Статус: каркас | полная. Реентерабельность: да | нет.

## Назначение
<1–2 фразы>

## Вход
- state.phase == "<prev>"; артефакты: <…>
- Если нет: <действие>

## Наводящие вопросы (дефолты)
- **Q1 <вопрос>?** Дефолт: <значение> — <обоснование>.
  Проверка: <как убедиться>.

## Действия
1. Проба ФС: <Glob-паттерны>.
2. …
3. Запись артефакакта <path>.

## Выход
- Артефакт: <path>
- state.json: <поле> → <значение>; decisions: +D-xx

## Гейт
содержательный | тривиальный. Вопросы: <…>

## Изоляция записи
- Разрешено: <пути>
- Запрещено: <пути> → патч-предложение
```

## Метки заменяемости в тексте

- `<!-- L3: пример -->` … `<!-- /L3 -->` — канонический пример, можно
  подменять под конкретный проект без перестройки фазы;
- `<!-- L2: drivers.<key> -->` — точка подключения драйвер-варианта;
  фаза читает ключ из state.json и подключает файл из `drivers/`;
- ссылка на другую фазу — всегда через реестр SKILL.md §D, не напрямую
  на внутренности соседнего файла (иначе замена соседа ломает фазу).

## Как добавить новую фазу

1. Создать `phases/<name>.md` по шаблону выше.
2. Вписать в реестр SKILL.md §D (полнота — честно).
3. Определить место в графе: чей выход — её вход, кому — её выход.
4. Если фаза порождает артефакты — описать их в state-contract.md
   (layout) и при необходимости bump `stateVersion`.
5. Если фаза должна запускаться параллельно — описать изоляцию и
   порядок reduce в SKILL.md §F.
