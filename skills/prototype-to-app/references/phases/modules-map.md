# Фаза: modules.map

Статус: каркас. Реентерабельность: да — работает батчами из очереди
`state.modules.queue`.

## Назначение

Параллельная сборка модулей (map-reduce): по субагенту на модуль
батча, типы первыми, reduce у оркестратора. Фаза — диспетчер; сам
домен проектируется в под-фазе `module-plan`.

## Вход

- `state.phase == "modules.map"`; skeleton завершён; фонд DS v1 готов
  (`artifacts/design-system.md`).
- Для каждого модуля батча — подтверждённый план
  (`artifacts/modules/<id>/plan.md`) и типы (`types.md`).
  Нет плана → сначала `module-plan`, в батч не включать.

## Наводящие вопросы (дефолты)

- **Q1 Размер батча?** Дефолт: 3 модуля (preset можно больше, домены
  меньше). Обоснование: reduce-стоимость растёт с числом агентов.
- **Q2 Состав первого батча?** Дефолт: 1 эталонный preset-модуль
  (вырабатывает образец) + 2 простых. Крупные домены — после того,
  как образец и refactor-цикл обкатались.
- **Q3 Уровень параллелизма модуля?** Дефолт: preset — 1 агент;
  крупный домен — 2 (service ‖ views после types); сетки — отдельным
  батчем, никогда вперемешку.

## Действия

1. Сформировать батч (вопросы Q1–Q3; порядок очереди уже задан в
   shell-decisions).
2. Для каждого модуля: прогнать под-машину
   `plan → types → [service ‖ views] → glue → review`,
   отражая прогресс в `modules.items[<id>].subphase`.
3. **Диспетчеризация map**: субагент получает промт = план модуля +
   types + правила изоляции (SKILL.md §F) + нужные реестры (DS,
   классификатор) + уровень полировки вёрстки
   (`drivers.uiPolish` → состав уровней:
   `skills/components/references/polish-levels.md`). Агенты
   запускаются параллельно (Task, одна сессия = один батч сообщений).
4. **Reduce**: собрать патч-предложения агентов (всё, что вне их
   изоляции), применить конфликты по порядку: shared-кандидаты →
   в отчёт refactor (не применять молча), конфиги shell → применить
   оркестратору, расхождения с планом → вопрос.
5. По завершении батча → фаза `refactor` (цикл).

## Выход

- Артефакты: код модулей батча, применённые патчи.
- state.json: `modules.items[*].status` батча, `phase → "refactor"`.

## Гейт

Содержательный перед диспетчеризацией: состав батча, число агентов,
кто какой модуль. После батча гейт перекладывается на refactor.

## Изоляция записи (для субагентов)

- Разрешено: папка своего модуля + его точка регистрации.
- Запрещено: shared/, дизайн-система, конфиги shell, чужие модули,
  `.app-build/**` — всё это патч-предложением оркестратору.
