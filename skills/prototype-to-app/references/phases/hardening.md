# Фаза: hardening

Статус: каркас. Реентерабельность: да (чек-лист можно гонять повторно).

## Назначение

Свести приложение к эталонному состоянию: состояния экранов, доки,
сборка. Проверяется инвариант всей машины: ширина (каркас) набрана,
глубина (модули) закрыта, фонд канонизирован.

## Вход

- `state.modules.queue` пуст; последний refactor-цикл без кандидатов.

## Наводящие вопросы (дефолты)

- **Q1 Формат доков модулей?** Дефолт: платформенный шаблон
  (`docs/modules/<id>/<id>.md`: цель / вид / поведение / открытые вопросы /
  тех-заметки). Открытые вопросы — обязательная секция (недоделки
  фиксируются, а не прячутся).
- **Q2 Что считать «эталоном готовности»?** Дефолт: typecheck + lint +
  build чистые; каждый экран проходит §48-аудит; персистентные моки
  переживают reload.

## Действия (чек-лист)

1. **§48-аудит**: каждый экран каждого состояния — тривиальный проход
   браузером (dev-browser): загрузка, пусто, ошибка, отказ в доступе,
   не найдено. Отсутствующие состояния — добить.
   Правила браузерных проб (уроки прогонов):
   - **Сначала убедись, что открыт нужный проект**: `title` страницы и
     первые строки `body.innerText` должны соответствовать проекту.
     В монорепо порт не идентифицирует проект (один vite-стартёр на
     все `PROJECT_APP`/env) — при сомнении найти процесс
     (`lsof -nP -iTCP -sTCP:LISTEN` + `ps eww -p <pid>` по env).
     HTTP 200 ничего не доказывает для SPA.
   - **Геометрию проверяй числами, не скриншотами**:
     `getComputedStyle` на ключевых селекторах (padding, border-*,
     grid-template-columns, line-height, flex-wrap) сверяется с
     каноном прототипа; адаптив — `setViewportSize` + повторная
     проба. Внутри `evaluate` — только plain JS, без TS-кастов.
   - **Адаптив — отдельным проходом** `<!-- L2: drivers.adaptivity -->`:
     те же маршруты на 320/390/416 по методике `drivers.adaptivity`;
     критерий чистоты — `scrollWidth == clientWidth`, скролл внутри
     `.table-wrap` — норма, не перелив. Перед пробой ждать
     контент-селектор (моки асинхронные — иначе ложно-отрицательное
     «чисто»); фактическую ширину брать из `clientWidth` (viewport
     dev-browser скейлится).
2. **Доки**: по одному файлу на модуль (Q1) + корневая карта модулей.
3. **Сборка**: typecheck / lint / build — чисто.
4. **Проба реального использования**: пройти сценарий прототипа
   целиком (клик-тур по всем модулям).
5. **Полировочный проход до L2** `<!-- L2: drivers.uiPolish -->`:
   если `drivers.uiPolish != "l2"` и UI готов — предложить подъём
   уровня (скелетоны 1:1, фейды медиа, свапы, микро-попы; состав и
   флоу «драфт → полировка» —
   `skills/components/references/polish-levels.md`). Исполняется
   скиллом `components` по экранам с дырами аудита (не блокирует
   done); итог — секция «UI-полировка» + эталоны в
   `skills/PROJECT.md` проекта.
6. Открытые вопросы — в доки; `state.phase → "done"`.
7. Хостинг — не часть hardening: если проекту нужен деплой/CI —
   скилл `deploy` (резолв — §I); прод-готовность
   (хардкод-аудит, env-обвязка, скорборд) — скилл `production`
   (резолв — §I).

## Выход

- Артефакты: доки модулей, чистая сборка.
- state.json: `phase → "done"`, итоговый `stale: []`.

## Гейт

Содержательный: отчёт аудита + список открытых вопросов — отпустить
в прод или вернуть конкретные пункты в очередь (`modules.queue`).

## Изоляция записи

- Разрешено: всё в пределах проекта (фаза финишная; расширенные
  права осознанные).
- Осторожно: `.app-build/**` — только предписанный диф фазы.
