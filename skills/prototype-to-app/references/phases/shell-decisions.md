# Фаза: shell-decisions

Статус: каркас (вопросник полный, детальные сценарные инструкции
допишутся по обкатке). Реентерабельность: да.

## Назначение

Зафиксировать договорённости об оболочке и границах приложения: что
делает shell, какие модули существуют, кому что видно. Самая дорогая
фаза по стоимости ошибки — все последующие фазы потребляют её записи.

## Вход

- `state.phase == "shell-decisions"`; прототип прочитан (экраны
  перечислены из навигации прототипа).

## Наводящие вопросы (дефолты)

Shell и платформа:

- **Q1 Роутинг?** Варианты: url-роутинг с deep links (дефолт для
  многоэкранных: F5 и шеринг ссылок) / внутренний стейт контроллеров
  (мелкие режимы — визарды, табы) / без роутинга. Нюанс: сегменты
  «внутри экрана» (шаг визарда) — локальный стейт, не URL.
- **Q2 PWA?** Дефолт: нет — у прототипа нет офлайн-требований.
- **Q3 Auth-гейт?** Варианты: без входа / вход без ролей / вход с
  ролями (дефолт для клубных приложений — вход с ролями: прототип
  обычно показывает переключение перспектив).
- **Q4 Роли и доступ?** Если роли есть: список ролей; какие модули
  каким ролям видны (enabled-предикаты). Дефолт: одна роль «участник».
- **Q5 Стартовый модуль** после входа. Дефолт: главная/лента.
- **Q6 Кросс-модульные переходы?** Дефолт: через маршрут shell
  (`route.navigate`), прямые импорты между модулями запрещены.

Границы модулей (главный вопрос фазы):

- **Q7 Таблица модулей**: каждому экрану прототипа — модуль, маршрут,
  доступ по ролям, природа (preset = стандартный CRUD-экран;
  домен = сложная предметика; сетка = сквозная функциональность,
  например мессенджер). Экраны без модуля и модули без экранов —
  повод остановиться и спросить.
- **Q8 Принадлежность сущностей**: какая сущность чья (у сущности
  ровно один модуль-владелец; остальным — доступ через сервис
  владельца или подъём в shared).

## Действия

1. Пройти навигацию прототипа, перечислить экраны.
2. Провести Q1–Q8 (содержательный гейт; AskUserQuestion по блокам:
   shell, роли, таблица модулей).
3. Записать `artifacts/modules-registry.md` (таблица Q7) и D-записи
   по всем вопросам; краткие факты — в `state.shell`.

## Выход

- Артефакт: `artifacts/modules-registry.md`.
- state.json: `shell.*`, `modules.queue` (порядок: preset первыми),
  `phase → "skeleton"`; decisions: +D по Q1–Q8.

## Гейт (содержательный)

Таблица модулей целиком перед пользователем: подтверждить / изменить
границы / пометить сомнительные (сомнительные идут в очередь последними
— к их моменту фонд DS и рефактор-циклы уже разовьются).

## Изоляция записи

- Разрешено: `.app-build/**`.
- Запрещено: код проекта (решения без кода; код начнётся в skeleton).
