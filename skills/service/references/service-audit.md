# Аудит сервиса: оси зрелости

Карта «что вообще можно улучшить в доменном сервисе» для скилла
`service` (SKILL.md §6): ревью существующего, приёмка после
расщепления или создания нового. Аудит ≠ «чинить всё»: карточка
фиксирует фактическое состояние, чинится релевантное запросу,
остальные дыры — в открытые вопросы (кандидаты в доработки модуля).

## Как читать карточку

Ось → чекпойнты → отметка **✓ есть / ✗ нет / — не применимо**.
Канон — SKILL.md §2–3; эталоны — живые сервисы u-kon (репо
Termin89/u-kon): organizations (канон-эталон расщепления), requests
(крупнейший мок: аудит-журнал, id-фабрики, нотификации),
notifications (ленивые коллекции, kind-словарь). У чекпойнта без
эталона правило написано прямо в тексте. Ссылки на файлы — от корня
u-kon.

## Ось 1. Персистентность

- Класс мока расширяет `PersistentMock` (in-memory — только для
  лёгких сервисов осознанным решением); семантика ядра —
  `references/persistent-mock.md`.
- `schemaVersion` объявлен и снабжён **историей версий схемы
  комментарием** в конструкторе: v2: …; v3: … — читатель понимает,
  что уже мигрировало (эталон requests: v7 — разделение id/number,
  v10 — closedFrom).
- LS-ключи сервисного scope `u-kon:<service>:*`; маркер пересева
  `<project>:<service>:__seeded` сравнивается с версией (ставит ядро,
  сервису достаточно не мешать).
- Публичный `reset()` не переопределяется без причины; пересев
  вычищает и медиа-префикс сервиса — ядро делает это само.

## Ось 2. Кеш-контракт

- Кеш-ключи запросов — с общим префиксом сервиса:
  `["<service>", "list"]`, `["<service>", "item", id]` (эталон
  requests: `["requests", "list"]`, `["requests", "request", id]`,
  `["requests", "audit"]`).
- Каждая мутация в контроллере заканчивается перечиткой
  `getQueryPort().invalidate(["<service>"])` — одна инвалидация
  кроет списки, детальные и производные выборки.
- Мутация **не патчит** стейт страницы вручную — write-through и
  перечитка, иначе два источника правды о записи.

## Ось 3. Гварды и инварианты

- Гварды живут в mock.ts — вторая линия после валидации UI (как
  отклонил бы сервер): квоты, единственность, статусные машины.
- Доменные ошибки — классы в types.ts с `readonly code` из union:
  контроллер показывает баннер по коду, не парсит сообщение
  (эталон `OrgQuotaError` → баннер партнёрской админки,
  src/ui/pages/partners/views/admin/OrgAdmin.tsx).
- Мутации идемпотентны или задокументированы как намеренно
  не-идемпотентные (номера max+1 при гонке могут дублироваться —
  мок одного клиента, не сервер).
- Тихие сбоящие побочные эффекты (аудит-запись, пуш уведомления)
  гасятся `.catch(() => {})` и не рвут доменную операцию.

## Ось 4. Нотификации

- Пуш — побочный эффект мутации через приватный хелпер
  `notify(input)` → `void notificationsService.push(input)
  .catch(() => {})`: fire-and-forget (эталоны organizations/mock.ts,
  requests/service/mock.ts).
- Id события детерминированный `<kind>-<сущность>-<адресат>`:
  повтор события обновляет запись, а не дублирует (put = upsert);
  потребитель может различать подсобытия префиксом id
  (`requests-respond-*` — отдельный тумблер в notifications).
- Kind — из словаря `AppNotificationKind`; новый kind или формат id
  согласован со schemaVersion notifications (пересев вычищает
  осиротевшие).

## Ось 5. Актёры и владение

- Мутации со следом «кто сделал» принимают актора параметром
  `{ name, email }` (`OrgActor` / `RequestActor`); контроллер берёт
  пользователя из сессии — **мок сессию сам не читает**.
- Снапшот актора пишется в запись / версию / журнал аудита, а не
  только в лог.
- Уровни доступа (none/own/any) решает домен — матрица ролей в
  permissions/app-слое (u-kon: src/app/roles.ts, `AccessLevel`);
  мок не дублирует решение, только честно отвечает на запрос.

## Ось 6. api-стаб

- Класс api-стратегии `implements XService` — зеркало **всего**
  интерфейса: пропуск метода ловит TS (цепочка аннотаций:
  `implements` на классе + `defineService<XService>` в service.ts —
  см. грабли в playbook.md).
- Все ручки бросают ошибку «не подключён» (эталон organizations:
  хелпер `NOT_CONNECTED("<что>")` на каждую ручку) — выключение
  флага мока показывает полный путь сетевого сбоя (errorBus).
- Заглушки не возвращают фейковых данных — честный сбой лучше
  молчаливой лжи.

## Ось 7. Медиа

- Загружаемый контент — blob → MediaRef (строка-ключ IndexedDB),
  не data-URL в записи: записи LS лёгкие, блобы переживают пересев
  данных.
- Ref может делиться между записями (сиды указывают на один blob) —
  GC вне мока: удаляет только пересев по префиксу сервиса
  (`clearMediaByPrefix`).
- Сид-медиа — стабильные ref (`messenger/seed-<messageId>`, не
  `upload-<rand>`): пересев не плодит дубликаты блобов (эталон
  messenger/service/seedMedia.ts).

## Ось 8. Связи с другими сервисами

- Разрешённые направления: lookup метаданных (resources →
  organizations; session → applications, organizations;
  notifications → settings; requests → messenger, organizations)
  и продюсер уведомлений (все → notifications).
- Рантайм-циклы запрещены; тип-импорт в обратную сторону допустим
  (applications/types ← session) — типы стираются, цикла нет.
- Страницы друг друга не импортируют — только сервисы;
  потребители идут через публичный вход `<id>/service`, не во
  внутренние файлы.
- Пробой связи гасится: lookup чужого сервиса с `.catch` и
  осмысленным деградированием (уведомления без настроек — чистые
  дефолты; превью чата без чата — пустое).

## Ось 9. Сидирование

- Есть сиды → seeds.ts с `SEEDS`/фабриками; нет сидов → файла нет,
  коллекции ленивые (`collections: { items: () => [] }`), записи
  создаёт первая мутация (эталоны: notifications, permissions,
  settings, applications).
- Пересев честно **стирает пользовательские правки LS** — поэтому
  любое изменение структуры или сидов сопровождается
  schemaVersion++ (маркер `__seeded` не совпал → clear + пересев);
  проверять при ревью каждой правки сида.
- Сиды несут те же инварианты, что и мутации (квоты, статусы) —
  иначе демо начинается с «битого» состояния.
