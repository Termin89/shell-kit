# /production

Подготовка к продакшену: повторяемый аудит «прод или нет» + env-обвязка
сборки. Полномочия по умолчанию: **скан и стату — всегда; env-обвязку
(механику) чинит сам; всё остальное — план**, а не молчаливые правки.

Посылка платформы: точки смены мока на прод уже есть (ITransport /
HttpTransport, `mockFlags` у стратегий defineService, PersistentMock,
errorBus). Прод = инвентаризация + переключение, а не переписывание.
Задача скилла — сделать таблицу переключателей видимой и считать её
повторяемо.

## A. Флоу: scan → scoreboard → wiring → plan → verify

Линейный, реентерабельный: каждый шаг пишет артефакт, повторный запуск
пересчитывает стату и делает diff с прошлым прогоном.

### 1. scan — инвентарь

- Паттерны — `references/scan-patterns.md` (grep-набор + правила
  уровней по умолчанию). Слои: App/services-конфиг (baseUrl,
  getToken, **mockFlags — главная таблица переключателей**),
  сервисы-моки, auth, сборка (vite.config: sourcemap/base), env
  (мало `import.meta.env` = нет env-слоя).
- Выход — черновик таблицы: `файл:строка / категория / цитата /
  уровень по правилу`.

### 2. scoreboard — стата «прод или нет»

- Домены и критерии — `references/checklist.md`. Уровень 🔴 блокер /
  🟡 осознанный мок-этап / 🟢 готово назначается **правилом домена,
  не на глаз**; 🟡 правомерен только со ссылкой на решение
  (MEMORY / decisions / дока).
- Хранение:
  - `docs/production.md` — итоговый скорборд (последний прогон:
    дата, коммит, счёт по доменам, список 🔴, вердикт);
  - `docs/production/runs/run-<date>.md` — полный снимок прогона;
    append-only, не перезатирается.
- **Diff с прошлым прогоном обязателен** (улучшилось / деградировало /
  не изменилось). Прогон №2+ начинается с чтения `runs/`: без истории
  нет diff'а, без diff'а стата бесполезна.

### 3. wiring — env-обвязка (чинит сам)

Механика без дизайн-решений, контракт — `references/env-contract.md`:

- `.env.example` + типизация `ImportMetaEnv` + fail-fast валидация
  при старте;
- `baseUrl` → из env (дефолт `""` = same-origin за реверс-прокси);
  мок-константа в `getToken` → чтение из сессии;
- `mockFlags` → читаемость из env (`VITE_MOCK_*`);
- прод-режим сборки (`--mode production`, sourcemap off) + скрипт.

Границы: осознанные моки **не выключаются** — mockFlags меняет только
владелец решения; скилл их показывает. Правка, меняющая поведение, —
в план, не в wiring.

### 4. plan — план из статы

- Каждый 🔴/🟡 → пункт: что / где / кто решает / чем чинится.
- Нетривиальные фиксы (auth на реальный бэкенд, error-репортер,
  CSP-заголовок) — через скилл `feature`, по одному; CSP на nginx —
  совместно с `deploy`.
- Нерешённое — в «Открытые вопросы» скорборда, не теряется.

### 5. verify

- Повторный скан после wiring: скорборд пересчитан, diff показывает
  эффект прогона.
- Сборка в прод-режиме чистая: typecheck / lint / build.
- `docs/production.md` закоммичен — стату видно в ревью.

## B. Правила

- В `VITE_*` ничего секретного: всё попадает в бандл — проверка
  входит в скан. Секреты — только окружение раннера/сервера.
- Уровень 🟡 — не снисхождение, а договор: без ссылки на решение
  («мок-этап, ждать transport этапа C») пункт считается 🔴.
- Безопасность — инвентаризация и рекомендации
  (`references/security.md`); чинить — по плану и с согласия.
- Реентерабельность: прерванный прогон можно повторить; артефакты
  прошлых прогонов не перезатираются.

## C. Интеграции

- **deploy**: перед деплоем deploy-скилл читает `docs/production.md`
  и показывает 🔴-блокеры **предупреждением** — решение за человеком,
  деплой не блокируется.
- **prototype-to-app**: production идёт после hardening, до/рядом
  с deploy — финальная проверка машины перед выпуском.
- **feature**: пункты плана с изменениями кода делегируются feature.

## D. Точки роста (каркас честно)

- Error-репортер прода (errorBus → внешний сервис): точка
  подключения, реализация — по кейсу.
- Перф-аудит (Lighthouse, размер чанков) — вне текущего каркаса.
- Стата как HTML-страница (как docs у prototype-to-app) — по запросу.
