# Поверхность безопасности

Уровни: 🔴 чинить до прода · 🟡 риск с записанным решением «принято» ·
🟢 норм. Каждый риск — с контекстом «как эксплуатируется и что стоит
защитой сейчас»: не пугать, а объяснять.

## Типовая таблица (по платформе shell-kit)

| Место | Риск | Уровень | Рекомендация |
|---|---|---|---|
| Мок-токен в `getToken` | авторизация фиктивна | 🔴 | реальный токен из сессии |
| Пароль не проверяется | вход любым паролем | 🔴 (мок-этап: 🟡 с решением) | api-стратегия сессии |
| Секрет в `VITE_*` / репо | попадает в бандл/историю | 🔴 | перенести в окружение |
| `innerHTML` / `eval` | XSS | 🔴 | не использовать (в платформе нет) |
| Сессия в localStorage | XSS → угон сессии | 🟡 | при чистой XSS-поверхности — приемлемый этап; прод-цель — httpOnly-cookie (на бэкенде) |
| Нет CSP | амплитуда XSS-атаки | 🟡 | мета-тег или заголовок nginx (совместно с deploy) |
| Sourcemaps в проде | чтение исходников | 🟡 | выключить в прод-режиме |
| Внешние fetch (демо-медиа) | CORS-зависимость, трекинг-пинг | 🟡 | заменить источники на свои к продоу |
| `credentials: "include"` same-origin | — | 🟢 | штатно |

## Что в платформе уже хорошо (фиксировать в скорборде)

- Нет `dangerouslySetInnerHTML` / `innerHTML` / `eval`.
- Секретов в репо нет; fetch с таймаутом и abort.
- Ошибки классифицируются (errors-слой), модульный ErrorBoundary с
  retry, запросы эмитят в errorBus.

## Правила скилла

- Скилл **инвентаризирует и рекомендует**; чинит — план и feature,
  с согласия. Молчаливые «улучшения безопасности» запрещены —
  меняют поведение незаметно.
- Рекомендации про nginx-заголовки (CSP, HSTS) — через deploy-скилл:
  там правила правки чужого конфига (бэкап → правка → `nginx -t` →
  reload).
- Пароли/токены не логировать и не вставлять в скорборд цитатами —
  в отчёте место находки, не значение секрета (мок-константы
  (`tok-mock`) можно, реальные — никогда).
