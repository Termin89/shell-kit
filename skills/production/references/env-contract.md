# Env-контракт сборки

## Переменные (дефолтный набор)

| Переменная | Смысл | Дефолт |
|---|---|---|
| `VITE_API_BASE_URL` | baseUrl транспорта/сервисов | `""` = same-origin за реверс-прокси |
| `VITE_MOCK_<SERVICE>` | mockFlags точечно (`VITE_MOCK_FEED=false`) | не задан → как в коде |
| `VITE_LOG_LEVEL` | verbose в dev / warn в прод | по режиму сборки |

Проект может расширять набор; контракт = имена, дефолты и правило
секретности ниже.

## Правила

- В `VITE_*` только публичное: **всё попадает в бандл**. Секреты —
  окружение раннера/сервера. Проверка на секреты — часть скана.
- `.env*` в .gitignore; коммитится только `.env.example`.
- Режим ≠ окружение: dev-сервер тоже может ходить на прод-API через
  `.env.local`; `--mode production` влияет на артефакт (sourcemap,
  подстановки), а не на то, куда смотрит dev.

## Обвязка (что чинит скилл в wiring)

1. **Типизация** `src/vite-env.d.ts`:

   ```typescript
   interface ImportMetaEnv {
     readonly VITE_API_BASE_URL?: string;
     readonly VITE_LOG_LEVEL?: string;
   }
   interface ImportMeta {
     readonly env: ImportMetaEnv;
   }
   ```

2. **Конфиг**: `import.meta.env.VITE_API_BASE_URL ?? ""` → в
   services-конфиг App (дефолт same-origin — правильный за nginx);
   мок-константу в `getToken` заменить чтением из сторА сессии.

3. **`.env.example`** с комментарием к каждой переменной (что, дефолт,
   пример) — единственный коммитящийся env-файл.

4. **Fail-fast валидация** до bootstrap: обязательные для прода
   переменные отсутствуют → console.error с внятным текстом и рендер
   заглушки, а не пустой экран/падение в рантайме посреди модуля.

5. **Скрипты**: прод-сборка `--mode production` (монорепо —
   `project:<p>:build:prod`, репо проекта — `build:prod`); в
   vite.config по режиму выключается sourcemap (dev-режим — как
   было).

6. **mockFlags из env**: чтение `VITE_MOCK_*` в App поверх значений
   в коде; сами флаги скилл не переключает — только делает
   переключаемыми.

## Границы wiring

Механика, не меняющая поведение без ведома: если правка меняет
семантику (реальный логин, реальный API) — она в план/feature, даже
если выглядит маленькой.
