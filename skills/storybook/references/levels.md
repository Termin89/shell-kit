# Уровни каталога: декораторы и фикстуры

Каждый уровень классификатора получает свою секцию каталога, свой
декоратор и источник фикстур. От дешёвого к дорогому.

| Уровень | Декоратор | Источник фикстур | Обязательный набор |
|---|---|---|---|
| Примитив ui-слоя ядра | theme.css проекта | props-матрица | все варианты типизированных пропсов + disabled/состояния |
| Блок shared | theme.css | данные из сидов сервисов | дефолт + граничные (пустой список, длинный текст, бейджи всех тонов) |
| Виджет | `ShellProvider` + AppState-фикстура | матрица ролей проекта | роли × состояния shell (auth/не-auth, activeModule) |
| Страница | `ShellProvider` (если нужен контекст) | **ветки vm-union** | все status-ветки §48 + ключевые content-режимы × роли |

## Правила

- **Story = вызов чистой вьюхи с vm.** Контроллеры в stories не
  участвуют — их роль выполняют фикстуры. Это следствие контракта
  «вьюха на пропсах»; если страницу нельзя так отрендерить — нарушение
  контракта, зафиксировать запах.
- **§48-набор страницы обязателен**: loading / empty / error / denied /
  notFound — по одной story на ветку union. Каталог становится
  визуальным §48-аудитом без запуска приложения.
- **Роли**: страница/виджет с `enabled`-предикатом или правами —
  story на каждую роль (клиент видит корзину черновика, партнёр —
  «Входящий» бейдж и т.п.).
- **Фикстуры из сидов**: берём сущности из персистентных моков
  (сиды сервисов), а не сочиняем. Сидов на граничный случай нет —
  фикстура- производная, пометить комментарием.
- Именование stories: `PR-<уровень>/<Компонент>/<случай>`
  (например `P-примитив/Button/варианты`, `S-страница/Requests/empty`).

`<!-- L3: пример story страницы из ветки vm-union -->`
```ts
import type { Meta, StoryObj } from "@storybook/react";
import RequestsPage from "../ui/pages/requests/RequestsPage";

const meta: Meta<typeof RequestsPage> = {
  title: "S-страница/Requests",
  component: RequestsPage,
};
export default meta;

// ветка union → story, §48-набор обязателен
export const empty: StoryObj<typeof meta> = {
  args: { mode: "list", pane: "list", status: "empty",
          onPaneChange: fn, onRetry: fn },
};
export const content: StoryObj<typeof meta> = {
  args: { mode: "list", pane: "list", status: "content",
          requests: SEED_REQUESTS, /* … */ },
};
```

## Порядок генерации

1. Примитивы ui-слоя ядра — каркас матрицы; варьируются только типизированные
   пропсы, layout-обвязка — минимальная.
2. Блоки shared — по реестру DS (если проект собран машиной) или по
   папке `ui/shared/`.
3. Виджеты — только каркасные (app-shell): навигация/топбар по ролям.
4. Страницы — по реестру модулей; сначала эталонный модуль проекта
   (из PROJECT.md), остальное по очереди.
