# UI-паттерны: как именно сделать операцию

Решающее дерево для clarify. Вход — кейс операции (что правим, где
стоит пользователь, сколько полей, как часто). Выбор всегда
проверяется аналогом проекта (эталон в PROJECT.md) — расхождение с
деревом из-за эталона допустимо и фиксируется в решении.

## Дерево

```
Где пользователь при вызове операции? Что правим?
├─ Просматривает список/карточку, правка редкая, контекст короткий
│   → МОДАЛКА: подтверждение, короткая форма (≤5 полей);
│     mobile ≤768 — bottom-sheet/drawer
├─ Поля видны на экране, правка частая, сущность «своя»
│   → INLINE: карандаш ↔ view/edit внутри карточки
│     (эталонный паттерн правки материалов)
├─ Полей много / нужна валидация / редактируется сущность целиком
│   → ФОРМА-ПАНЕЛЬ: отдельный режим vm (mode: "editing") в том же
│     модуле; состояние — локальный стейт до сабмита
├─ Создание сущности в 2+ логических шагах
│   → ВИЗАРД: шаги = локальный стейт (не URL), сабмит — мутация;
│     черновик — персистентная сущность со статусом draft
├─ Новый самостоятельный экран с deep-link (F5, шеринг)
│   → РЕЖИМ-ЭКРАН: подпапка модуля (wizard/, detail/…), сегмент URL
└─ Прогрессивное улучшение без смены экрана
    → КОНТРОЛИРУЕМЫЙ ВИДЖЕТ: view/edit внутри карточки, правки —
      onChange наверх, персистентность решает владелец данных
```

## Правила поверх дерева

- **Один паттерн на операцию**; смешение (модалка с визардом внутри)
  — стоп-сигнал пересмотреть ветку.
- **URL или локальный стейт?** Шаги/табы внутри операции — локальный
  стейт; результат операции, на который ведут ссылки и F5, — сегмент
  маршрута модуля.
- **§48 операции** выбирается паттерном: модалка/панель — pending на
  кнопке + баннер сбоя с ретраем; inline/виджет — состояние
  «Сохраняем…» на месте + ретрай; визард — сбой в финальном шаге,
  панель не переключается.
- **Права решают видимость входа**: нет права — вход не рендерится
  (disabled-кнопка вместо скрытия — только если это осмысленный UX,
  не по умолчанию).
- Мобильная адаптация — обязательный вопрос при модалке/панели
  (брейкпоинты проекта, см. PROJECT.md).

## Что фиксировать в решении

`паттерн → почему (кейс) → чем отличается от эталона → §48 операции`
— одной строкой в решении (D-запись или док модуля).
