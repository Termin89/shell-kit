# Playbook агента — плановый проход одного модуля

Один агент = один модуль `src/ui/pages/<id>/`. До кода прочитать:
`projects/<app>/skills/PROJECT.md` (канон, эталоны, запреты) и этот
playbook. Git — только read-only (status/diff/log): коммитит
оркестратор. Таск-лист и чужие модули — не трогать. Ошибки tsc/oxlint
в чужих файлах — WIP соседей по волне, игнорируются.

## Порядок фаз

recon → 1 структура → 2 аудит-оси + чинка → 3 L2 → 4 верификация →
5 доки → отчёт. Фаза структуры для одноэкранного модуля вырождается в
проверку канона (components/ уже норм) — остальное полностью.

### 0. recon

- `ls` модуля на глубину 2; `wc -l` по tsx/ts (контроллер, экраны).
- Состав экранов: `views/<экран>/` (если уже по канону), иначе
  роут-детекция контроллера (цепочка `matchPath` хвоста маршрута) —
  экран = ключ vm-union = будущая папка views/.
- `docs/modules/<id>/<id>.md` + `<id>-memory.md` (если есть) — история,
  грабли прошлых сессий, WIP-файлы пользователя (их не трогать).
- Если будет структурная фаза — снять DOM-пробы ДО (см. фазу 4).

### 1. структура (мультиэкранным)

- `views/<экран>/` + `shared/`: папка экрана = файл слайса
  `controllers/` = ключ vm-union; блоки зоны плоско рядом; кросс-экранные
  блоки — `shared/`. Канон — component-levels.md (decision tree +
  «Один экран — один tsx в корне»), эталон — feed в u-kon.
- Перенос `git mv`, имена файлов сохранить. Импорты переписывать
  sed-батчами ПО СПИСКУ ФАЙЛОВ ИЗ git (не по памяти — на feed файл
  выпадал из батча). Арифметика глубины: файл в `views/<z>/` — корень
  модуля `../../…` (config/vm/service), ui-shared `../../../../shared…`,
  соседний модуль `../../../<m>/…`; файл в `shared/` — `../…`,
  `../../../shared…`. cwd между Bash-вызовами сбрасывается — пути
  абсолютные или cd-префикс в каждом батче.
- Контроллер > ~1000 строк → тонкий корень (роут-детекция + сборка
  vm-union) + `controllers/<экран>.ts` слайсы + `vm.ts` (контракт
  вьюх); экран > ~250 строк → декомпозиция: один блок — один файл,
  корень-tsx = оглавление. Вложенные тернарники → derive-функции.
- Докстринги/комменты со старыми путями (`components/…`) починить.

### 2. аудит-оси (все экраны)

- **§48**: loading (скелетон, не пустота) / error + «Повторить» /
  empty / denied / no-results отдельной веткой («Сбросить фильтры»);
  битые deep-link → notFound/denied, не error.
- **a11y**: роли, aria-*, лейблы интерактивов; **клавиатура**:
  таб-порядок, Enter/Space на кликабельных карточках, Esc на модалках.
- **Контраст**: мерить на фоне первого непрозрачного предка (фон
  страницы даёт ложные цифры).
- **mobile 390**: без горизонтального скролла, сетки в одну колонку;
  честные 390 — только CDP `setDeviceMetricsOverride` (окно клампится
  ~433), override СНЯТЬ сразу после проверки (застрявший молча убивает
  trusted-ввод).
- **data-name**: полное покрытие интерактивных узлов.
- Дыры чинить сразу по канону проекта; найденные дефекты — в отчёт.

### 3. L2 (полировка, канон components)

- Скелетон 1:1 геометрии живого контента: кап обложек (maxHeight =
  контент), высоты строк = реальные line-box (не Tailwind-шаги), резерв
  N строк — одной обёрткой суммарной высоты (лишний ребёнок flex-col =
  лишний gap); role=status, призраки aria-hidden.
- Фейд-ин медиа: заливка-плейсхолдер на обёртке, фейд на img (opacity
  на img гасил бы фон), onLoad + img.complete в layout-эффекте.
- Свап режимов useSwapAnimation (порядок режимов), оптимистичные
  мутации + stale-while-revalidate-стэш по ключу записи (канон —
  контроллер feed), микро-анимации от производного стейта — только
  useEffect. Эталоны модуля/соседей переиспользовать, не изобретать.

### 4. верификация (гейт статуса)

- Из корня монорепо: `npx tsc -p tsconfig.app.json --noEmit` — свои
  файлы чисты; `npx oxlint projects/<app>/src` — так же. Build НЕ
  гоняешь — один на всех в closeout.
- Свой порт: в монорепо `PROJECT_APP=<app> npx vite --port <выдан>
  --strictPort` (из корня), в репо проекта — `npm run dev --
  --port <выдан> --strictPort`. Браузер — skill dev-browser, страница
  `pass-<id>`: экраны во всех применимых состояниях §48, data-name,
  клавиатурный проход, mobile 390 (CDP, снять override), скелетоны
  ловить MutationObserver-ом в init-скрипте (однокадровые loading
  waitForSelector не ловит). React-инпуты — только `locator.fill()`.
- Структурная фаза: DOM-пробы до/после побайтово идентичны.
- Перед смоуками перечистить свои LS-ключи (`<app>:<модуль>:*`), после
  — перечистить снова (данные демо чистые).

### 5. доки

- `docs/modules/<id>/<id>.md`: секция структуры актуальными путями
  (views/+shared/ список), датируя смену.
- `<id>-memory.md`: запись с датой — фазы × результат, что нашлось,
  чем проверено; новые грабли — в раздел граблей.

## Отчёт оркестратору (схема возврата)

- модуль; фазы × результат (сделано / дыр не было / пропущено — почему);
- изменения: файлы и ход (переносы, декомпозиция, чинки);
- верификация: tsc/oxlint по своим файлам, пробы (какие, вердикт),
  идентичность DOM-проб структурной фазы;
- риски и хвосты (что не сделано, что подсмотрено на будущее);
- права: заблокированные действия (инструмент/команда отклонены,
  нет права на запись/запуск) — какое действие, на чём споткнулся;
  не глотать молча;
- WIP-файлы, которые не тронут.
