# Dev-инструменты (devtools)

Панель разработчика: `defineDev(config)` — компонент с плавающей
кнопкой «DEV» (портал в body, z-60; панель — z-70, превью — z-80).
Гейтинг DEV — на совести приложения (`import.meta.env.DEV && <DevTools/>`);
слой тянет React, потому — отдельный subpath-экспорт `shell-kit/devtools`.

## Панель-drawer (v0.9.2)

Дефолтная панель — немодальный drawer слева на всю высоту окна
(стиль Chrome DevTools / Storybook):

- **слева, поверх приложения** (~¼ экрана: ширина
  `clamp(300px, 25vw, 480px)`, capped до `calc(100vw - 16px)`; на
  узких ноутбуках минимум 300px может быть шире четверти — контенту
  нужен запас, осознанно);
- **немодальная**: без бекдропа — приложение видно и кликабельно,
  dev следит за живым приложением, пока переключает стратегии;
  закрывается Esc / ✕ / тумблером FAB;
- **overlay, а не push**: layout тестируемого приложения не
  сдвигается — замеры вёрстки под панелью не меняются;
- **скроллится только контент** — шапка и табы вне скролла
  (flex-колонка);
- **анимация — только transform** (~260 мс, вход и выход,
  `cubic-bezier(0.2, 0.8, 0.2, 1)`); `prefers-reduced-motion` —
  мгновенно; после закрытия фокус возвращается на FAB;
- body-скролл не блокируется; `aria-expanded` FAB честен на время
  анимации выхода (панель ещё в DOM).

Кастомная `view` рендерится как раньше — без drawer-хрома
DefaultDevPanel (контракт не меняется).

## Табы панели

### API · Сервисы

Каталог стратегий (`getServiceCatalog`): радио стратегий, черновик,
«Применить» — override в LS (`writeDevStrategyOverrides`) + reload.
При открытии панели прогреваются чанки всех модулей декларации
(через инстанс `defineApp` из AppContext или конфига) — каталог полон
без статических импортов сервисов в dev-чанке проекта.

### Состояния

Два раздела:

- **Каталог · декларации** — реестр деклараций (`module/states`
  v0.9.0): чанк модуля грузится → декларация в реестре. На состояние:
  путь/хост, статическая access-матрица (`projectAccess` по ролям
  вселенной, зачёркнутая роль — недоступна; рантайм-guard — маркер
  «guard?»), чипы вариантов. Кнопка «превью» — офлайн-оверлей.
- **Живые машины** (помечено «живое») — смонтированные машины
  (`devId`-реестр): goto-прыжки (внутренние состояния — прямо из
  тулы), журнал-кольцо с replay. Обратная связь с реальным
  приложением; каталог деклараций первичен.

Чипы модулей вверху — реальная навигация `/<id>` (монтирует машину).

### Пользователь (при `config.user`)

Пресеты офлайн-сессии: строка текущего (`currentLabel()`) + кнопки
пресетов (`apply(presetId)`). shell-kit не знает модели пользователя:
проект строит пользователя сам (пример u-kon: `buildMockUser` → LS
`u-kon:session` → reload, по паттерну стратегий сервисов — без
сетевых запросов).

## Офлайн-превью (PreviewHost)

Оверлей с **изолированной машиной** по декларации из реестра:

- источник адреса — история в памяти (`createMemoryHistory`, засев
  `demoPath`): goto/replace пишут в неё, реальный URL и роутер
  приложения не трогаются, первый sync уже резолвит целевое
  состояние (без мигания initial);
- та же история — порт `RouterProvider` вокруг сцены: вьюхам с
  router-хуками (`usePath`/`useNavigate`) есть откуда читать —
  без провайдера хуки бросают; навигация из вьюхи остаётся в
  изоляции и синхронизирует машину (`port.subscribe → sync`,
  после goto — no-op);
- `skipOnEnter` — onEnter состояний не вызывается (канонизация
  адреса, авто-прогоны токенов живого приложения не запускаются);
- без `devId`/журнала — реестр живых машин не засоряется;
- роли — чипами нижнего бара, `getRoles` через ref: смена роли без
  пересоздания машины; запрещённое состояние откатывается в fallback
  (чипы показывают факт из снапшота);
- нижний бар: состояния (листание), варианты текущего состояния,
  роли; закрытие — Esc, клик по затемнению, кнопка;
- вьюхи, требующие контекста экрана, рендерятся через `preview`-
  обёртку записи реестра (пример: vm-контроллер auth-экрана,
  `AuthVmContext.Provider`); прочие сбои рендера гасит ErrorBoundary —
  карточка вместо белого экрана.

Работает и с экрана входа: панель монтируется вне ShellGate, каталог
не зависит от живых машин.

## Кастомная вьюха

`view: (api: DevPanelApi) => ReactNode` — панель под дизайн-систему
проекта: api отдаёт каталог/черновик/действия сервисов и `user`-
конфиг (пресеты, currentLabel, apply). Плавающая кнопка остаётся
стандартной.
